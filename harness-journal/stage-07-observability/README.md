## 前置条件
- 阶段6 代码已合并并部署

## 计划步骤

### 01 - 可观测性验证
- 检查日志采集是否正常
- 检查指标上报是否正常
- 检查告警规则是否就位
- 确认 Trace 链路追踪可用

### 02 - 线上烟雾测试
- 验证关键路径可用性
- 检查 API 响应时间和错误率
- 确认前后端联动正常

### 03 - DRR 长循环
当线上验证发现问题时：
1. 确认问题根因
2. 修正环境配置（更新约束/规则/脚本）
3. 回到「写代码」节点重新开发
4. 重新走编码 → 验证 → 合并 → 部署全链路

### 04 - 决策菱形：线上验收通过?
- 通过 → 功能标记为 passing，进入熵管理
- 失败 → 触发 DRR 长循环

## 对应 Harness 核心机制
- DRR（Detect → Recover → Re-verify）长循环
- 可观测性是 DRR 的感知器官
- 线上验收不通过不是终点，而是修正环境的起点

## 产出物
- 可观测性配置
- 线上测试报告
- DRR 循环记录（如有）
- feature_list.json 状态更新为 passing
