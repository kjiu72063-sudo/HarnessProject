# 阶段5 — 自校验与反馈循环

> 状态：⬜ 待执行

## 前置条件
- 阶段4 编码完成
- 代码已通过 mvn verify 闸门

## 计划步骤

### 01 - 测试结果决策菱形
- 运行完整测试套件
- 决策菱形：测试结果?
  - 通过 → 进入阶段6（合并）
  - 失败 → 进入问题分类

### 02 - 问题分类
- 老问题（规则已定义）→ 查询对应文档找到解决方案
- 新问题（需新建规则）→ 尝试自行解决

### 03 - 解决成功决策菱形
- 决策菱形：解决成功?
  - 是 → 进入文档反馈循环
  - 否 → 升级处理（人工介入）

### 04 - 文档反馈循环（核心机制）
问题解决后必须执行：
1. 更新 AGENTS.md 硬性规则
2. 更新 boundaries.md
3. 新增/强化 Linter 规则
4. 更新 progress.txt
5. 更新 feature_list.json 状态
6. 提交 Git

### 05 - 虚线回路
- 反馈回路（虚线）回到「写代码」节点
- 重新执行：写代码 → mvn verify → 测试结果?

## 对应 Harness 核心机制
- 反馈循环：失败 → 修复 → 规则完善 → 避免复发
- 每次失败都是环境设计不完善的信号

## 产出物
- 测试报告
- 反馈循环日志（feedback_log 表）
- 更新后的 AGENTS.md / 规则文档
- 更新后的 progress.txt
