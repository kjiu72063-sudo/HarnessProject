# 01 - 编写 AGENTS.md

## 步骤名称
AGENTS.md（地图模式，50-100行）

## 执行时间
2026-08-17

## 前置条件
- 初始化 Agent 已完成
- 技术栈已确认

## 执行内容

采用"地图模式"而非"百科全书模式"编写 AGENTS.md。

### 设计原则
1. 控制在 50-100 行
2. "你想做什么 → 去哪里看" 比 "这是什么" 更有效——面向任务而非面向知识
3. 硬性规则单独列出，这些是 CI 会强制验证的

### 文档结构

```
# AGENTS.md
## 项目简介              ← 一句话描述
## 技术栈基线             ← 版本锁定，不允许擅自升级
## 快速导航               ← 表格：你想做什么 → 去哪里看
## 硬性规则（CI 会验证）   ← 7条规则
## 目录结构               ← 关键目录说明
## 提交规范               ← feat/fix/refactor/docs/test/chore
```

### 7 条硬性规则
1. 前端调用后端 API 统一走相对路径 `/api/...`，禁止硬编码域名/IP/localhost
2. 后端 Python 代码禁止裸 `print()`，统一用 `logging`
3. 前端禁止 `as any` 和隐式 `any`
4. 新增 API 必须有对应类型定义（Pydantic schema + TS 类型）
5. LangGraph Node 必须是纯函数，接收 State 返回 State
6. 端口: 前端 Vite 固定 5000，后端 FastAPI 固定 8000
7. 不修改 .coze 中的 sub_id

## 产出物
- `AGENTS.md` — 地图模式入口文件

## 验证结果
- 行数在 80 行左右，符合 50-100 行规范
- 快速导航表覆盖 9 个场景
- 硬性规则可被 CI 验证

## 备注
AGENTS.md 是 Agent 进入代码仓库时看到的第一份指南。后续每次 Agent 犯错后，应更新此文件（Harness 的"文档是活的反馈循环"原则）。
